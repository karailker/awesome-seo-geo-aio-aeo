---
description: Quick general check of the whole site in one command: connections, a sample crawl, search, traffic, performance and one combined report. No tool choice needed. Read-only.
argument-hint: "[origin] (default: origin from awesome-seo.json)"
---

Run the quick site check for `$ARGUMENTS`. Read-only: no write tool is called and no approval is needed. It samples the site (at most 50 URLs, last 28 days), so say that the results describe a sample. For the full version use `/site-audit`. Rules: `docs/SECURITY-AND-APPROVAL.md`, `docs/AGENTS-AND-SKILLS.md`.

1. Settings. If `awesome-seo.json` exists in the project, run `npx -y -p @karailker/awesome-seo-core@0.2 awesome-seo config` and use its sources; stop and show the error if it is invalid. If it does not exist, use `$ARGUMENTS` as the origin, and say that Search Console and Bing use defaults guessed from the origin and that GA4, Yandex and Merchant are off. Suggest `awesome-seo config --init --origin <origin>` at the end. If neither is available, stop and ask for the origin.
2. Connections. Call the five health tools (`mcp__plugin_awesome-seo_google__google_health`, `mcp__plugin_awesome-seo_bing__bing_health`, `mcp__plugin_awesome-seo_yandex__yandex_health`, `mcp__plugin_awesome-seo_performance__performance_health`, `mcp__plugin_awesome-seo_crawl__crawl_health`). A source with a missing credential is recorded as missing data and skipped; it does not stop the check.
3. Database. Run `npx -y -p @karailker/awesome-seo-core@0.2 awesome-seo migrate` and `npx -y -p @karailker/awesome-seo-core@0.2 awesome-seo seed --origin <origin>`.
4. Sitemap and sample crawl. Call `mcp__plugin_awesome-seo_crawl__crawl_discover_sitemap` with the sitemap from the settings, then ingest it as `/sitemap-sync` does. Crawl with `mcp__plugin_awesome-seo_crawl__crawl_fetch_pages` using `url_cap: 50`, then `crawl-ingest`. Say the run is a sample. Tell the user a 50-URL run takes about a minute.
5. Access. Call `mcp__plugin_awesome-seo_crawl__crawl_check_access` on the origin and keep the JSON for `--access`.
6. Search, period = the last 28 days ending 3 days ago (Search Console data is delayed). Make the same calls as `/seo-audit` steps 3 and 4: Search Console pages and queries, GA4 sources and pages when the settings enable GA4, Bing with `mcp__plugin_awesome-seo_bing__bing_search_stats` and `bing_page_stats` (`site` from the settings, `output_path` under `bing/`), Yandex when the settings enable it. Each failed call is recorded as missing data and skipped. Never fill in values.
7. Performance. Call `mcp__plugin_awesome-seo_performance__performance_psi_run` (`strategy: "mobile"`) for the home page and up to two other URLs from the sample, and `mcp__plugin_awesome-seo_performance__performance_crux_query` for the origin. Keep lab and field values separate, as `/perf-audit` does.
8. Report. `mkdir -p data/reports`, then run `npx -y -p @karailker/awesome-seo-core@0.2 awesome-seo audit --origin <origin> --mode quick --start <start> --end <end> --access data/<access file> --gsc ... --ga4 ... --bing ... --yandex ... > data/reports/site-check-<host>-<date>.md`. Pass only the files that were written.
9. Show the report path, the "Needs attention" list, the "Missing data" list, and the performance values with their lab or field label. Quote the report's own wording. Do not add conclusions the reports do not state. End with what `/site-audit` would add.
