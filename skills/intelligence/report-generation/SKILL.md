## Purpose
Produce the audit report in the fixed section order from `docs/ROADMAP.md` P12. The report separates what was measured from what is inferred.

## When to use
- Every `/seo-audit` run. The report is generated by `buildSeoAuditReport` in core and printed by `pnpm seo:audit`.

## Inputs
- Site origin, period (start and end), and Search Console observations ingested for that period.
- Sitemap pages ingested for the site.

## Tools
- `pnpm seo:audit --origin <origin> --start <start> --end <end> [--gsc <file>]`

## Method
The report has these sections, in order:
1. Scope: site, period, sources included and not included.
2. Data sources and date ranges: observation count, freshness, last collected, sitemap count.
3. Missing data: one line per missing source.
4. Findings: each with severity, confidence, affected count, description, and evidence count.
5. Sitemap and Search Console reconciliation.
6. Evidence check: candidates, kept, dropped, reasons.
7. Limitations.

## Evidence rules
- Every finding cites observation ids. Findings without evidence are dropped by the gate.
- Thresholds are project-defined and labeled as such.

## Output schema
Markdown with the seven headings above, in that order.

## Quality checks
- Section order matches the list above.
- No section states a number the data does not contain.

## Missing and failed data
- Missing source: say so in `## Missing data` and in the section that would have used it.
